# Policy

Why each rule in blueprint exists, and what enforces it. A rule enforced by a cop or lint rule fails CI; a rule enforced by AGENTS.md is followed by whoever writes the code, person or agent. To change a rule, change it here and in whatever enforces it, in the same PR.

## Design

| Rule                                                                                                                                                                                                                                              | Why                                                                                                                                                                             | Enforced by                                                                                  |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Compose, don't inherit. Pass collaborators in, share code through modules or functions, and describe contracts as interfaces (RBS interfaces in Ruby, `interface`/types in TypeScript). Errors and framework-mandated parents are the exceptions. | Inheritance couples a class to its parent's implementation, so a change in the parent ripples into every child. Composition keeps each piece swappable and testable on its own. | `Bottrall/NoInheritance` (`AllowedParents` for framework parents), `bottrall/no-inheritance` |
| Inject collaborators; construct concrete ones only at the application edge. Type a dependency as the smallest interface it needs.                                                                                                                 | Code that reaches for its own collaborators can't be tested without patching them, and can't be reused with another implementation.                                             | AGENTS.md (Code style)                                                                       |
| Prefer functional style: return new values instead of mutating, and keep side effects behind clear boundaries. A class only when an instance has identity, lifecycle or mutable state.                                                            | Pure functions are easier to read, test and reuse. A class with only class methods is a module.                                                                                 | AGENTS.md (Code style)                                                                       |
| Expected outcomes are returned as values; exceptions are for programmer errors and unrecoverable states.                                                                                                                                          | Exceptions used for control flow hide the paths a caller has to handle.                                                                                                         | AGENTS.md (Code style)                                                                       |
| `Data.define` for a record whose fields don't change; a class once it needs a method, a default or a field that changes; never `Struct`.                                                                                                                                                              | Data classes are concise and rbs-inline types them, but Steep can't see methods in their block. rbs-inline marks every `Struct.new` argument optional, so a missing field type-checks and fails at runtime; mutation belongs in a class with typed accessors.                                  | AGENTS.md (Ruby typing)                                                                             |
| Every lint suppression says why: `# rubocop:disable X -- <reason>`, `// oxlint-disable-next-line x -- <reason>`.                                                                                                                                  | A silent suppression outlives the reason it was added, and the next reader can't tell whether it's still needed.                                                                | `Bottrall/RequireDisableReason`, `bottrall/require-disable-description`                      |

## Testing

| Rule                                                                                                   | Why                                                                                                                                            | Enforced by                                                     |
| ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Don't mock code you own; inject a real, lightweight fake. Mock a third party only at its API boundary. | A mock checks how the code is built, not what it does, so it passes while the real collaborator has changed. A fake keeps the contract honest. | `Bottrall/NoMocking`, `bottrall/no-mocking`                     |
| One assertion (or `expect`) per test.                                                                  | A failing test then names exactly one broken behaviour.                                                                                        | `Minitest/MultipleAssertions` (Max 1), `vitest/max-expects` (1) |
| Every module of behaviour has a test file; in TypeScript it sits beside the source.                    | Untested behaviour is the behaviour that breaks unnoticed.                                                                                     | `bottrall/require-colocated-test`; AGENTS.md (Testing) for Ruby |
| TypeScript coverage holds per file: 100% of functions, 75% of statements, on every run.                | A per-file floor stops one well-tested file hiding an untested one, and running it always means a local pass is a CI pass.                     | vitest thresholds, `bin/test`                                   |

## TypeScript

| Rule                                                                                                                                    | Why                                                                                                                         | Enforced by                                                |
| --------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Don't annotate return types; let them be inferred (type predicates and assertion signatures excepted).                                  | An inferred type can't drift from the implementation; an annotation can, and then it lies.                                  | `bottrall/no-explicit-return-types`                        |
| No type casts (`as T`, `<T>x`); use `satisfies`, type guards or assertion functions. `as const` is fine.                                | A cast asserts a shape nobody checked.                                                                                      | `bottrall/no-type-casts`                                   |
| Values are camelCase, constants included.                                                                                               | One naming rule for every value; PascalCase stays for types and components.                                                 | `bottrall/no-screaming-case`                               |
| Named exports only.                                                                                                                     | Named exports are refactor-safe and searchable; a default export can be imported under any name.                            | `bottrall/no-default-export`                               |
| State is held in Preact signals: `useSignal` in a component, `signal`s in a plain module for shared state. `react/immutability` is off. | Signals update only what reads them. The React rule reports every `signal.value` write, which is the only way to write one. | AGENTS.md (ts-app); `@bottrall/oxlint-config` (`app.json`) |
| Tailwind classes are written so the linter can read them.                                                                               | Built-up class strings escape the Tailwind lint rules (unknown, conflicting or duplicate classes).                          | `bottrall/no-unlintable-classes`, better-tailwindcss rules |

## Ruby

| Rule                                                                                                                                                                                            | Why                                                                                                                                   | Enforced by                                                |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Steep reports every diagnostic as an error, and diagnostics are never disabled in the Steepfile.                                                                                                | A type checker with advisory warnings stops being read.                                                                               | `Steepfile` (`D::Ruby.all_error`), AGENTS.md (Ruby typing) |
| One shared RuboCop style: RuboCop's defaults where they exist (single quotes, trailing commas), plus the line-break cops, `extend_self`, compact nesting, and Metrics off except block nesting. | Every repo reads the same, and defaults mean less config to keep in sync. Size metrics produced suppressions rather than better code. | `rubocop-bottrall` (`config/base.yml`)                     |

## Process

| Rule                                                                                                                       | Why                                                                                                         | Enforced by                                      |
| -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| Everything runs through `bin/` with the standard names; `bin/check` before calling a change done, `bin/ci` before pushing. | People, CI, Claude and the deps fixer all run the same thing the same way, so a local pass means a CI pass. | The shared `bin/` scripts; CI calls only `bin/*` |
| PR titles are Conventional Commits; PRs are squash-merged.                                                                 | The title becomes the commit on `main`, which release-please turns into the version bump and changelog.     | `pr-title` required check; repo ruleset          |
| Dependencies update weekly through `bottrall/deps`; linter, formatter and blueprint releases come in their own PR.         | Small, regular updates instead of rare big ones, and a new lint rule never holds up the rest.               | `renovate.json` extending `github>bottrall/deps` |
